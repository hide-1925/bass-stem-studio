## 2. 再生同期・音割れ（`web/measure.html`）

6 ステムの同じ位置（1.0 秒から 0.75 秒おき）にクリックを置いた合成ステムを、アプリと同じエンジンで再生。出力で検出したクリック時刻と「画面に表示される再生位置」を比較（目標 100 ms 未満）。

| 条件 | ステム間ずれ（最大） | 表示誤差（平均 / 最大） |
|---|---|---|
| 100% | 0.0 ms | 1.5 / 2.3 ms |
| 50% | 0.0 ms | 4.4 / 4.7 ms |
| 150% | 0.0 ms | 0.9 / 2.2 ms |
| 100%・ループ 2.0–5.0 秒 | 0.0 ms | 1.6 / 2.1 ms |
| 70%・ループ 2.0–4.0 秒 | 0.0 ms | 3.0 / 3.3 ms |
| 再生中に 100% → 130% | 0.0 ms | 1.4 / 2.5 ms |

- 上の表は FX ラック（ステムごと＋マスターの EQ / コンプ）を組み込んだ後に再計測した値（組み込み前と差なし）。コンプの先読み遅延（1 段 6.0 ms × 2 段 = 12.0 ms）は起動時に実測して補正している。
- ステム間ずれが 0 なのは、6 ステム（12ch）を **1 つの伸縮ノード** で処理しているため（読み出し位置を共有）。
- 表示誤差は Web Audio のグラフから音が出る時点までを含む。OS / デバイスの遅延は `AudioContext.getOutputTimestamp()` で補正しているが、物理的な計測（ループバック録音）は未実施。
- ループ終点 B の **ちょうど上** にあるクリックは、伸縮処理が B の少し先まで読むため、ジャンプの瞬間に一部が鳴る一方で表示は A に戻っている（70% ループで 2 件。表からは除外）。実曲では B 直後の音がごく短く聞こえることがある。

| 音割れ試験 | 結果 |
|---|---|
| ベース以外の 5 ステム +10 dB（ベース 0 dB）＋全ステムに大音量の低音ベッド、再生中にミュート切替 | リミッター前ピーク **+22.7 dBFS** → リミッター後 **−1.00 dBFS（クリップなし）** |
| サーバー側の自動ヘッドルーム（全サンプルで加算ピークを厳密計算） | 3 分曲・全ステム 0 dB：ピーク −2.9 dBFS → 減衰なし。ベース以外 +10 dB：ピーク +7.2 dBFS → 全体を 8.2 dB 下げる（計算 80–100 ms） |

ブラウザのメモリ（3 分曲を読込）：メインスレッドの JS ヒープ 4 MB。ステム本体は AudioWorklet に転送済み（float32・12ch で約 371 MB）。

## 3. 採譜精度（`tools/evaluate.py --testsets`）

試験データ：`tools/make_testset.py` が生成する 16 小節の合成曲（各 92 音、正解 MIDI / TAB 付き）。
ベース音色はエレキベースに近い加算合成（warm / bright / thin = 基音減衰）で、Demucs が「ベース」として分離できる（SDR 約 14 dB）。
**ベース単独** と **ミックス → Demucs 分離 → 採譜** を別々に評価。
判定：onset ±50 ms・音高 ±50 cent・オフセットは無視（mir_eval）。

音符 F 値（適合率 / 再現率）：

| 曲 | 条件 | fused（既定） | basic_pitch | pyin |
|---|---|---|---|---|
| warm | ベース単独 | 0.902 (0.82/1.00) | 0.891 | **1.000** |
| bright | ベース単独 | 0.843 (0.73/0.99) | **0.844** | 0.402 |
| thin | ベース単独 | 0.920 (0.85/1.00) | 0.889 | **1.000** |
| warm | ミックス | **0.814** (0.69/1.00) | 0.798 | 0.791 |
| bright | ミックス | **0.732** (0.58/0.98) | 0.719 | 0.717 |
| thin | ミックス | **0.705** (0.59/0.87) | 0.661 | 0.636 |

| 指標（fused） | ベース単独 | ミックス |
|---|---|---|
| onset 誤差（MAE） | 6.1–7.2 ms | 5.3–6.3 ms |
| 音高正解率（onset が一致した音） | 0.92–0.96 | 0.93–0.97 |
| 見落とし / 92 音 | 0–1 | 0–10 |
| 余計な音符 | 16–33 | 42–63 |
| TAB 弦・フレット一致率（正しく検出された音） | 0.62–0.66 | 0.56–0.71 |
| TAB 一致率（音高が完全な場合の最適化単体） | 0.65–0.69 | 同左 |

- **ミックスの精度はベース単独より低い**（F 値で 0.09–0.22 低下）。主因は他楽器のベースステムへの漏れによる余計な音符。
- 信頼度による識別（ミックス 3 曲）：しきい値 0.5 で **余計な音符の 51% を低信頼（オレンジ）として強調、正しい音符の誤強調は 1%**。
- TAB の「一致率」は合成データ作成時に選んだ運指（例：E2 を E 弦 12 フレットで弾く）との一致。音高が完全でも 0.65–0.69 なので、不一致は検出ミスではなく運指の曖昧さによるもの。
- **合成音は実録音より簡単** なので、この数値は上限の目安として扱う。実録音の評価は正解 MIDI / CSV を用意して `python tools/evaluate.py --audio bass.wav --reference ref.csv`（ベース単独）、`... --audio mix.wav --reference ref.csv --separate`（ミックス）で行う。

### 残る誤認識の例（fused）

| 種類 | 例 | 原因（推定） |
|---|---|---|
| 余計（重複） | `2.10s A1`, `2.32s A1`（長い A1 の後半）/ `1.13s E1`（本来の音の 60–90 ms 前） | Basic Pitch が伸ばした音を分割したり、極低音の前に「前エコー」を出す。断片の結合は、試験で本物の連打まで消した（F 0.939 → 0.911）ため既定で無効 |
| オクターブ（下方向） | `G2 → G1`, `E2 → E1` | 前の音の残響や低域の漏れが、基音より下の「奇数倍音テスト」を通ってしまう |
| 5 度ずれ | `E1 → B1`, `D2 → G1`, `A2 → E2` | 第 3 倍音（+19 半音）を基音と誤認し、オクターブで丸めると 5 度ずれが残る |
| 見落とし | `E1` の連打（thin・ミックス） | 基音が弱い＋分離で連打のアタックが不明瞭になる |
